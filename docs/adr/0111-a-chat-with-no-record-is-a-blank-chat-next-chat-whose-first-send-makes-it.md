# A chat with no record is a blank chat-next chat whose first send makes it

Deleting the "New chat screen" switch leaves one case the old screen still owned: a chat the reader has opened but not sent in, which has no record to read. It now opens on a chat-next blank surface — the bot's face, an empty thread and the app's own composer, with the bot picker when the legacy layout is on. Nothing is written on mount. The first send calls `beginThread`, which makes the one conversation and hands the message over by its id, then replaces the address; the thread that mounts takes the handover once and sends it as the first turn. The blank surface never posts.

**Why not the two shorter paths.** Creating the record on mount would make an ordinary thread with nothing in it — a "New chat" row in `Recents`, a card in the bot's Main and a sync payload before the reader has said anything. Mounting `ChatNextThread` with no session would be purest "one screen", but every read, poll and store in that component is keyed by a session, so a session-less mode would be a second thread path inside the file that can least afford one. The blank surface is a sibling composition, not a second screen: it reuses the composer and the chat-next frame, and it exists because it has no session, not because it has a different job.

**One sender, as ADR 0096 says.** The first turn is sent by the thread that draws it, not by the surface that is about to unmount; the handover is the same path Main's `/thread` already proves. The rejected alternative — post from the blank, then navigate — would give one turn two owners. The blank surface is reachable today only where a record-less chat already arises, the legacy layout's `/`; under bot threads a chat starts at the bot's Main with `/thread`, which makes its record before it is drawn. If a record-less chat should be reachable from Main too, that is a new entry point, not a fourth verdict.
