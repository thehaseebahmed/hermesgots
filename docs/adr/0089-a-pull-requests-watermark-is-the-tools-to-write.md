# A pull request's watermark is the tool's to write

Every pull request the plugin opens ends with a line saying Gots wrote it: `Generated by
[Gots](https://hermesgots.dev), a Hermes plugin.`, under a `---` rule. It used to read `Generated by
[Gots Code](https://hermesgots.dev), a Hermes plugin.`, and for a while it carried the GitHub account's
no-reply address. Two things about it are the decision.

**One writer.** The mark is `ship.PR_MARK`, and `_described` is the only thing that writes it — on both
paths that set a description, the ship that opens the pull request and the update that rewrites one.
`update` was the hole: it added the closing line and nothing else, so any `action: 'update'` carrying
a body dropped the mark from a description that had it. No prompt instruction asks
for the mark and none may. A line the model writes is a line the model can word differently, put in
the middle, write twice, or leave out when it decides the template left no room — and the stage that
rewrites a description is a different run from the one that wrote it. The tool takes out any mark
standing on its own line outside a fence and appends exactly one at the bottom, so what a run believes
about who wrote the description cannot reach it. A mark a run buried mid-paragraph is left where it is,
as text, and such a description carries two — the cost of not scanning prose for a phrase.

**One shape, replaced rather than stacked.** The stamp recognises the mark it writes *and* the
`Gots Code … a Hermes plugin` line every pull request opened before this one carries, and replaces
what it finds. A description rewritten therefore migrates on its next body update instead of growing
two marks — and stamping one that already ends in the mark leaves it exactly as it was — while the
exact-substring test the old `_body` relied on, which would have appended a second mark beside a
reworded one, is gone. The `Closes #n` line stays above the mark, as it already did, so the one line
GitHub acts on is never the last thing in a description. A description is only touched when a body is
written: a `ship` against a pull request already open pushes the branch and writes no description, so a
description opened before this change keeps its old mark until a body update replaces it.

**No address, because a description is not where credit is counted.** The address was put there to
make the account appear among a repository's contributors, and it could not: GitHub counts
contributions from the commits that reach the default branch, and a line of a description is not one
of them. What carries that job now is the co-author trailer on every commit the tool writes
(`0090-gots-is-a-co-author-on-the-commits-it-writes.md`). A mark showing a mailbox nobody was meant to
write to cost the reader noise and bought nothing, so the line keeps the one part a reader can act on
— the link.

**Not switchable.** There is no parameter and no setting that drops the mark, for the reason the
`Closes` line has none: the tool is the only way a description is written, so what it writes is the
rule rather than a preference. A repository that bans machine-written lines in a description cannot
turn it off, which is the cost, accepted because a mark the product cannot guarantee is not a mark.

**Considered options.**

- **An instruction in the session prompt, telling the agent to end the body with the line.** Rejected.
  That is the shape the old mark drifted into — `plugin/README.md` claimed the instructions added it —
  and it leaves the mark's presence, wording and position to the model, in the run that writes the
  body rather than the one that reads it back.
- **A `watermark: false` parameter, or a host setting.** Rejected. Each is an opt-out by another name,
  and the parameter would be the model's to pass.
- **The account's no-reply address on the line.** Removed. It was there so the account would be
  credited, which the source of that credit never reads; the git identity carries it instead.
- **Dropping the old wording's "a Hermes plugin" clause.** Considered and not taken: the clause says
  what the line is as well as whose it is, so a reader meeting Gots for the first time learns it is a
  plugin from the sentence rather than from the link alone.

**Consequences.** A description's last three lines are the rule's, not the model's: a `---`, a blank
line, and the mark. The mark is 61 characters, and `MAX_BODY` is enforced on the body a run passes
before the mark is appended, so that path's worst case is 60,068 characters — inside GitHub's 65,536
limit. The fallback that lists the branch's commit subjects when a run passed no body is not capped by
`MAX_BODY`; it is as long as that log, and a log long enough to pass GitHub's limit is refused by
GitHub with its own answer. Both paths are covered in `plugin/tests/test_pull_request_tool.py`: the
exact literal, no address in it, one occurrence after a ship, one after a body update, a body that
already carries the mark keeping only one, prose that names the product without linking it surviving,
a mark written without angle brackets taken out, a bulleted mark, a quoted mark and the
old `Gots Code` mark replaced rather than duplicated, a fenced example of the mark left alone, a
body ending in an open fence or comment getting the mark outside it, prose that only mentions a fence
not being closed for it, and a title-only update leaving the body alone. No prompt text, no
`docs/prompts.md` and no mock prompt constant changes, because none of them ever described the mark;
the two prose claims that did — `AGENTS.md` and `plugin/README.md` — now say the tool writes it. Pull
requests opened before this change keep the `Gots Code` line until a body update replaces it.
