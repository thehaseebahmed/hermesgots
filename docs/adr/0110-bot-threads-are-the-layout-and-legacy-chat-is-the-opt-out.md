# Bot threads are the layout, and legacy chat UX is the opt-out

Bot threads — bots in the sidebar, each chat a thread in its bot — was a Developer experiment, read as `developer && botThreads`, so most devices never saw it and one switch meant both "may the sidebar be bots" and "which layout is this". The experiment has proved out: bot threads is now the layout on every device, and the Developer switch is inverted into **Enable legacy chat UX**, which restores the old `Recents` sidebar. The stored setting is one local `legacyChat` boolean, unset meaning bot threads; `botThreads` is retired, and a save sheds it along with the other retired keys. No migration and no Dexie bump: the old value is read nowhere.

**Why the opt-out is where it is.** The request put the switch in Developer rather than Appearance, and that is kept. It is a deliberate exception to the rule that a choice for everyone lives where everyone can reach it: the legacy layout is for the reader who knows they want it, and the Developer page — five taps on the version — is where the switches that outlive their experiment live. The cost is named: hiding Developer settings leaves the layout on and the switch five taps away again.

**What this replaces.** ADR 0065 put chat-next behind a Developer switch; the same cleanup deletes that switch and makes callability the only screen rule (ADR 0111). The two experiments were the last two settings that meant "out of the lab" rather than "how this device works"; removing them is what lets the Developer page hold links and diagnostics instead of product choices. The rejected alternative was keeping `botThreads` and flipping its default in place: it would leave a field whose name says the opposite of its switch, and would keep the developer AND in the one place every layout read goes through.
