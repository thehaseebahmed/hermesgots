# Settings show a value and the edit drills in

A bot's settings had grown into cards holding text boxes, model buttons and pickers side by side, so the screen is rebuilt on Samsung One UI's pattern: a card shows a value, and nothing inside it is editable. A row is a title over the value it holds, in the accent colour — *Not set*, muted, where it holds nothing — with a subtitle saying what the setting is for only where the row drills in or the purpose isn't otherwise obvious; there are no chevrons, since the value and the press are what mark a row tappable. Editing a text value opens the edit itself: a pushed screen below 1024px, a centred dialog card from it, labelled, with Cancel and Save committing once. A list that is only picked from opens a sheet below 1024px and the same centred card from it, searchable, with radio rows; a list that is only read drills in as a screen — a push below 1024px, the page pane from it. Switches, steppers, avatars and buttons act where they sit. The grouping softens with it: *Gots* and *Hermes* caption the cards on a page, *Bot Profile* captions its own, the bot-settings list carries none, and cards are separated by a gap rather than a heading. 1024px stays the app's one breakpoint; Material's 840dp expansion is recorded here as a later, app-wide change. Considered: keeping inputs in cards (what the tabs grew into, and what the reference screen rejects), a dialog for every edit (a whole screen for one field reads bare on a laptop, where the centred card does not), sheets at every width for picks (side drawers are for content, not for choosing), and adopting 840dp now (it would split the panes at one width and the edits at another).
