# A bot's General page is its own Hermes's General tab

Settings > Bot > General showed the bot itself: its Enabled switch, its notifications, its profile
— name, image, a connection test — and, under a second caption, the three Hermes keys the app had
learned to write. Everything else a bot's Hermes holds was out of reach from a phone, which is the
same fact that sends a dictation through the plugin instead of Hermes's own transcription route: the
Dashboard is a form for `config.yaml` and it runs on the host's loopback. The page is now the
Dashboard's Config > General tab, mirrored.

**The rows are the host's, not the app's.** The Dashboard's tab is generated by walking Hermes's own
config schema and keeping one category, so the list of keys is a property of the host that serves the
bot, not of this repo: it changes when Hermes changes, and it is spelled however that host spells it.
A table of keys written here would drift from it silently, and on a host arranged differently it
would be worse than silent — the plumbing does not reject a path nothing reads. Two spellings found
this way are the reason the rule is written down: `model.name` does not exist (it is `model.default`,
and Hermes canonicalises the old spelling on read), and fourteen of the tab's keys are top level
(`timezone`, `command_allowlist`, `file_read_max_chars`, …) even though the Dashboard files them under
_Session_ — so a write to `session.timezone` would create a key nothing reads, forever.

So the plugin answers the page from the host's schema — the keys, their kinds, a pick's choices, the
host's default behind each — and the app draws whatever it is given. It is the same bet ADR 0063 made
for the speech provider pages, and the same promise: a key Hermes adds later is a row without an app
release.

**The page draws an app's rows, not a Dashboard form.** The Dashboard puts a field in every row; this
app's settings show a value and drill into the edit (ADR 0055), and that holds here: a switch acts in
place, a value opens its edit — the field over one action bar, the host's default as its
placeholder, and _Reset_ leading _Save_ where the file holds a value (ADR 0105) — and a closed set
opens its pick, searchable where the host says the list is long enough to want it. A key the host only reads when its process starts says
so in its edit, since a write that appears to do nothing is the shape of a broken setting.

**Three rows the host's tab leads with are drawn here, and two of them are written elsewhere.**
Hermes's own General tab opens on the main model, the model's context window and the chain tried
after it, and a page that claims to mirror that tab while hiding its first three rows is not
mirroring it. So the page draws all three. Two of them — `model` and `fallback_providers` — keep the
writers that already own them: `switch_model` + `persist_model_selection` set a pick's provider and
base URL together, and the chain has a validated writer with a two-entry cap and a legacy key to drop.
A raw scalar write to either would leave the keys inconsistent, and two screens writing one key is the
failure the settings restructure's membership rule exists to prevent (ADR 0052) — so the page draws
those two rows and hands their taps to those routes. The third, `model_context_length`, is a host key
like any other: Hermes's own schema carries it as the Dashboard's field (its `0` meaning *detect it*)
while the value lives inside `model`, so the plugin maps that one path and sends the host's own
sentence about the zero for the row to show.

**What the page replaced moves onto the bot's own page.** The old General's rows — Enabled, Mute
notifications, Progress updates, the profile and the connection test — were the first thing a user
opened Settings > Bot for, and holding them behind a _General old_ page put a click between a bot and
the switch that turns it off. They are the bot's own rows, so they lead the bot's page under the
caption _Bot_, and every setting page follows in one card under _Settings_ (ADR 0106). `/general-old`
survives only as an address that redirects to the bot's page, so an old link still lands somewhere
true.

**General can be withheld, so the fallback stops being General.** The page needs a plugin that can
read the host's schema, so it is gated on the `general_page` feature. That breaks the app's one
fallback rule, which pointed every withheld page at General: a page gated on its own availability
cannot land on itself. A withheld page now lands on the bot's own page, which every bot has and which
needs nothing from the host — the same screen the list already is.

**The captions rule grows by one page.** Every row is a Hermes setting, so a caption naming an owner
would disambiguate nothing; the cards are captioned by the section the host files their keys under —
its first dot-segment, so `session.terminal_continue` sits under _Session_ — and the keys with no
segment, the 14 top-level ones such as `timezone` and the `paste_collapse_*` trio, sit in the page's
own uncaptioned card. The Dashboard's renderer puts those under a section of their own; this page
doesn't invent a grouping the key doesn't carry. ADR 0063 scoped that licence to the Speech-to-text page and
`AGENTS.md` said it licensed nothing elsewhere; this is the second page it covers, and the rule is now
stated by what makes a page eligible — a page whose cards are about what settings do, not who owns
them.
